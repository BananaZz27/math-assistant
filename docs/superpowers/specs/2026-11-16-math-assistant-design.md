# ผู้ช่วยคณิตศาสตร์และวิเคราะห์ข้อมูล: เอกสารออกแบบ (2026-11-16)

สถานะ: **โบ๊ทอนุมัติแล้ว** (ฉบับนี้เป็นการเขียนใหม่เป็นภาษาไทย เนื้อหาเดิม)

## 1. เจตนา (ทำไมถึงทำ)

โบ๊ท (นักศึกษาปี 3 วิศวกรรมหุ่นยนต์และระบบอัตโนมัติ) อยากได้ AI คู่หูแบบ Pelops-2 ในเรื่อง *Godzilla Singular Point* คือผู้ช่วยที่ช่วย **วิเคราะห์ข้อมูลและแก้โจทย์คณิตศาสตร์** โดยทำทีละขั้น หารูปแบบ (pattern) ลองสมมติฐาน และอธิบายว่า *ทำไม* ถึงได้แบบนั้น

เหตุผลที่สำคัญสำหรับโบ๊ท:
- โบ๊ทไม่ได้เรียนสายวิทย์-คณิตมาตอนมัธยม ผู้ช่วยจึงต้อง **สอนไปด้วยขณะแก้** ไม่ใช่แค่ให้คำตอบ
- ต้องการให้ **ใช้ออฟไลน์ได้**, มี **หน้าตาแบบ Console (แบบ A)** และ **เอาไปต่อกับโปรเจกต์อื่นได้** (เช่น แขนกล, ROS 2)
- ตัวละครเป็น **หุ่น "ลูกบาศก์" ต้นฉบับ (แบบ 2)** ไม่ใช่ตัวละครจากเรื่อง

## 2. เป้าหมาย

1. ถามโจทย์คณิตศาสตร์เป็นไทยหรืออังกฤษ แล้วได้คำอธิบายทีละขั้นพร้อมคำตอบที่ตรวจแล้ว
2. โยนไฟล์ CSV/Excel เข้าไปแล้วได้สรุป กราฟ และข้อค้นพบเป็นภาษาคน
3. ตัวเลขทุกตัวมาจาก **โค้ดที่รันจริง** (SymPy / pandas) ไม่เคยมาจากการคิดเลขในหัวของโมเดลภาษา
4. ทำงานได้โดยไม่ต้องใช้เน็ตเป็นค่าเริ่มต้น และสลับ "สมอง" ไปใช้โมเดลคลาวด์ได้เมื่อออนไลน์
5. โปรแกรมอื่นเรียกใช้ผ่าน API ในเครื่องได้
6. โค้ดแยกหน้าที่ชัดเจน คนอื่นมาแก้ต่อได้ง่าย (ตามสไตล์ที่โบ๊ทชอบ)

## 3. สิ่งที่ไม่ทำ (non-goals)

- ไม่ใช่แชตบอททั่วไป ไม่ใช่ผู้ช่วยเขียนโค้ด
- ไม่ลอกตัวละคร ดีไซน์ หรือชื่อจากอนิเมะ
- v1 ไม่มีระบบบัญชีผู้ใช้ ไม่มีโฮสต์บนคลาวด์ ไม่มีแอปมือถือ
- ไม่รับประกันว่าแก้โจทย์คณิตศาสตร์ระดับงานวิจัยได้

## 4. สิ่งที่ถือว่าล้มเหลว (anti-goals)

- ตอบผิดอย่างมั่นใจโดยไม่มีขั้นตอนตรวจสอบ
- ให้แต่คำตอบโดยไม่อธิบาย (โบ๊ทไม่ได้เรียนรู้)
- ต้องใช้เน็ตหรือ API เสียเงินแม้แต่งานพื้นฐาน
- โค้ดพันกันยุ่ง ปนกันระหว่าง UI, AI และตรรกะคณิตศาสตร์

## 5. ข้อจำกัด

- เครื่อง: HP Victus 16, การ์ดจอ RTX 4050 แบบโน้ตบุ๊ก (VRAM ประมาณ 6 GB ต้องยืนยันบนเครื่องจริง) โมเดลในเครื่องจึงต้องเล็ก ประมาณ 7-8B พารามิเตอร์ แบบบีบอัด (quantized)
- โบ๊ทเขียน Python และ C/C++ เป็นหลัก มีเวลา 1-4 ชั่วโมงต่อวัน ชอบคำอธิบายไทยผสมอังกฤษพร้อมอธิบายศัพท์เทคนิค
- โบ๊ทยังไม่คล่อง HTML ดังนั้น UI ต้องเล็กและมีคอมเมนต์ชัดเจน

## 6. แนวทางที่พิจารณา

| แนวทาง | คืออะไร | ข้อแลกเปลี่ยน |
|---|---|---|
| A. ออฟไลน์ล้วน | โมเดลในเครื่องผ่าน Ollama + เครื่องมือ Python | ฟรีและเป็นส่วนตัว แต่อธิบายได้ไม่ลึกเท่า |
| B. คลาวด์ล้วน | เรียก API คลาวด์เป็นสมอง | ฉลาดที่สุด แต่ต้องใช้เน็ตและเงิน ขัดกับข้อ "ออฟไลน์" |
| **C. ไฮบริด (โบ๊ทเลือก)** | แอปเดียว "สมอง" สลับได้ (ในเครื่องเป็นค่าเริ่มต้น คลาวด์เป็นทางเลือก) | เขียนเพิ่มเล็กน้อยตอนแรก แต่ครบทั้งสามข้อ |

## 7. สถาปัตยกรรม (ตกลงในบทสนทนา ผมลงรายละเอียดเพิ่ม)

สี่ชั้น หนึ่งชั้นหนึ่งหน้าที่:

```
ui/        หน้าเว็บสไตล์ Console (รันในเครื่อง)           -- แสดงแชต ขั้นตอนคำนวณ กราฟ สถานะ
api/       FastAPI บน localhost                           -- ประตูบานเดียว ทั้ง UI และโปรเจกต์อื่นใช้ร่วมกัน
brain/     อินเทอร์เฟซ "สมอง": LocalBrain (Ollama), CloudBrain (ทางเลือก)
tools/     เครื่องมือคำนวณและข้อมูล: SymPy, pandas, matplotlib ในตัวรันที่จำกัดสิทธิ์
character/ อวตารหุ่นลูกบาศก์ (SVG) + ตัวจัดสถานะ: ว่าง / กำลังคิด / เสร็จ / ผิดพลาด
```

ลำดับการทำงาน: คำถาม → api → สมองวางแผนว่าจะเรียกเครื่องมือไหน → เครื่องมือคำนวณ → **ตรวจคำตอบ** (เช่น แทนค่ารากกลับเข้าสมการ) → สมองอธิบายในภาษาของผู้ถาม → ui แสดงคำตอบ แผงขั้นตอน และกราฟ

กฎสำคัญ: สมองไม่เคยสร้างตัวเลขสุดท้ายเอง แค่วางแผนและอธิบาย นี่คือสิ่งที่ทำให้โมเดลเล็กในเครื่องใช้งานได้ดีพอ

## 8. หน้าตาและตัวละคร (โบ๊ทเลือก)

- หน้าตา: **Console (A)** โทนมืดแบบ HUD แผงขั้นตอนตัวอักษรโมโนสเปซ แชตซ้าย ขั้นตอนและกราฟขวา แถบสถานะแสดงสมอง (LOCAL/CLOUD) และเอนจิน ภาพตัวอย่างอยู่ในผืนผ้าใบ "Pelops Math Assistant Look Options"
- ตัวละคร: **หุ่นลูกบาศก์** ตัวสีฟ้าเขียวมุมมน หน้ากากตาเป็นแถบไฟสองดวง เสาอากาศมีจุดสีอำพัน สถานะ: ว่าง (เสาอากาศกะพริบช้า), กำลังคิด (ตาสแกน), เสร็จ (ตาสว่างขึ้น), ผิดพลาด (ตาหรี่) ภาพอวตารเปลี่ยนได้ ถ้าโบ๊ทอยากใช้ภาพของตัวเองในอนาคต

## 9. ส่วนที่ผมตัดสินใจเอง (โบ๊ทแก้ได้ทุกข้อ)

- ชื่อผู้ช่วย: ใช้ `[ASSISTANT NAME]` ไปก่อนจนกว่าโบ๊ทจะตั้ง ไม่ใช้ชื่อจากอนิเมะ
- UI: HTML ธรรมดา + JavaScript เล็กน้อยที่ FastAPI เสิร์ฟให้ ไม่ใช้เฟรมเวิร์กหนัก ผมเขียนให้ โบ๊ทไม่ต้องเขียนเอง
- โมเดลในเครื่อง: ตัวเลือกแรกคือตระกูล Qwen ขนาด 7-8B แบบบีบอัด แต่ **ต้องทดสอบบนโน้ตบุ๊กของโบ๊ท** (คุณภาพภาษาไทย ความเร็ว) ก่อนล็อกตัวจริง
- การรันโค้ด: เครื่องมือรันในโปรเซสที่จำกัดสิทธิ์และมี timeout ไม่มีเน็ต ไม่เข้าถึงไฟล์นอกโฟลเดอร์ทำงาน
- ภาษา: คำตอบตามภาษาของคำถาม สัญลักษณ์คณิตศาสตร์แสดงเป็น Unicode ธรรมดา (x², √) ใน v1
- v0 แก้เฉพาะคำตอบที่เป็นจำนวนจริง (real solutions)

## 10. สิ่งที่ยังเปิดอยู่

- ชื่อสุดท้ายของผู้ช่วย (โบ๊ท)
- จะใช้โมเดลคลาวด์ตัวไหนสำหรับ CloudBrain (ตัดสินตอนเริ่ม v3)
- ค่า VRAM จริงและผลทดสอบโมเดลบนเครื่องของโบ๊ท

## 11. ลำดับการสร้างที่เสนอ

1. v0: `tools/` + `brain/LocalBrain` ใช้งานจากบรรทัดคำสั่งได้ (แก้สมการหนึ่งข้อ สรุป CSV หนึ่งไฟล์) พร้อมเทสต์ที่ตรวจคำตอบกับค่าที่รู้อยู่แล้ว
2. v1: `api/` + `ui/` หน้า Console + สถานะของตัวละครลูกบาศก์
3. v2: ตัวอย่างการเอาไปใช้จากโปรเจกต์อื่น (เช่น แขนกล)
4. v3: CloudBrain และสวิตช์ LOCAL/CLOUD

## 12. หมายเหตุสำหรับผู้สร้าง

- แต่ละโฟลเดอร์ทำหน้าที่ของตัวเองเท่านั้น ห้ามมีคณิตศาสตร์ใน `ui/` ห้ามมี UI ใน `tools/`
- เขียนเทสต์ของ `tools/` ก่อน (สมการที่รู้คำตอบ CSV ขนาดเล็ก) ก่อนต่อสมอง
- ห้ามเอา API key ไปไว้ใน repo หรือเอกสาร
